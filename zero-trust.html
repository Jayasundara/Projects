01 / Project Background

Replacing AVD-dependent access with Zero Trust.

Before this implementation, users depended on Azure Virtual Desktop to reach staging applications and database resources. This introduced an additional access layer for users who only needed secure connectivity to specific STG services.

The project introduced a Zero Trust access model so approved users could securely connect from their own managed computers while access decisions were based on user identity, MFA, device security posture, and application policy.

02 / Project Requirements

Security and access requirements.

User & Resource Access

  • Allow users to access STG applications from their own managed computers instead of using AVD as the access path.
  • Provide secure access to STG web applications, databases, and APIs.
  • Use Cloudflare Zero Trust policies to control which users and devices could access specific resources.

Identity & Device Trust

  • Integrate Microsoft Entra ID for user authentication and MFA.
  • Integrate CrowdStrike Falcon with Cloudflare device posture so only approved and healthy managed endpoints were allowed.
  • Avoid directly exposing private Azure resources to the public Internet wherever Cloudflare Tunnel/private network access was used.
03 / Implemented Solution

Cloudflare as the secure access layer.

Cloudflare Zero Trust was deployed between users and the Azure staging environment. Users were enrolled with the Cloudflare One Client (WARP) on their corporate devices, while Cloudflare Access and Gateway policies evaluated user identity and device posture before protected traffic was allowed.

  • Cloudflare Tunnel connectivity was created for STG web applications.
  • Cloudflare Tunnel/private-network routes were created for STG database access.
  • Cloudflare Tunnel connectivity was created for STG APIs and internal services.
  • cloudflared connectors were associated with Azure resources, including VM-hosted services and web application origins.
  • Microsoft Entra ID was integrated as the identity provider and MFA was enforced.
  • CrowdStrike was integrated as a third-party device posture provider.

05 / Technical Design

Private connectivity and resource-specific access.

Cloudflare Tunnel Connectivity

cloudflared established outbound-only connectivity from Azure to Cloudflare, removing the need for directly reachable public IP exposure for tunnel-protected resources and supporting both HTTP and private non-HTTP access.

Web Application Access

STG web applications were protected with Cloudflare Access. After Entra ID authentication, Access evaluated policy before forwarding approved requests through the tunnel to the Azure origin.

Database & Private Network Access

Database traffic used Cloudflare private-network routing through WARP. Private IPs, hostnames or CIDR ranges were routed through Tunnel and restricted with Gateway policies based on identity and device posture.

API Access

STG APIs and internal services were routed through Cloudflare Tunnel and protected with Zero Trust policy controls so approved users and devices could reach only required services.

06 / Identity, MFA and Device Trust

Identity-aware and device-aware access decisions.

Microsoft Entra ID Authentication

Microsoft Entra ID was configured as the Cloudflare Access identity provider. Users authenticated with organizational identities and MFA requirements were enforced for protected access.

CrowdStrike Device Posture

CrowdStrike Falcon was integrated as a third-party posture provider. Cloudflare One Client and CrowdStrike endpoint data were used to evaluate security attributes including Zero Trust Assessment score, sensor score, operating-system score, device state and last-seen status.

Zero Trust Access Decision

1. User RequestUser initiated access from a managed corporate computer.
2. WARP RoutingCloudflare One Client routed private application or network traffic.
3. Identity + MFAMicrosoft Entra ID authenticated the user and MFA was verified.
4. Device PostureCrowdStrike posture was evaluated against policy.
5. Resource PolicyOnly approved traffic was forwarded through the correct Cloudflare Tunnel to Azure STG.

09 / Technical Summary

AVD dependency replaced by policy-driven Zero Trust.

The project replaced the previous AVD-dependent access method for selected STG resources with a policy-driven Zero Trust model. Users accessed approved staging web applications, APIs and database services directly from managed corporate computers through Cloudflare One Client.

Cloudflare Access and Gateway evaluated Microsoft Entra ID authentication, MFA and CrowdStrike device posture before granting access. Separate Cloudflare Tunnel and private-network routes connected Cloudflare to Azure-hosted staging resources. Because cloudflared established outbound-only connections, tunnel-protected origins did not require direct inbound exposure for the Cloudflare access path.

The completed design improved user experience while maintaining identity-aware, device-aware, least-privilege access to the STG environment.
