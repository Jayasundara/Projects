VMware Infrastructure Modernization

Modernized an aging bare-metal server environment into a VMware-based infrastructure with a clustered Production platform, separate Staging and QA environments, shared SAN storage, Fibre Channel connectivity, segmented management and workload networks, and controlled migration of legacy Linux systems.

01 / Executive Summary

From aging physical servers to structured virtualization.

CBL had been operating aging bare-metal servers and legacy systems that were increasingly difficult to support and maintain. The existing platform had no clearly separated Production, Staging, and QA environments, and backup protection had not been enabled for the legacy systems. These limitations increased operational risk and made maintenance, testing, and future infrastructure changes more difficult.

The project implemented a VMware virtualization platform. Production was deployed as a dedicated two-host cluster using HP DL580 servers, two HP P2000 SANs, Fibre Channel switching, and VMware ESXi 6.5. Separate STG and QA workloads were hosted on two HP DL320 servers without clustering. Dedicated management and workload VLANs and separate Production and STG/QA management switches created clear network boundaries, with both management switches connected upstream to the firewall.

Some older Linux workloads could not be migrated directly to ESXi 6.5. These systems were first converted into VMware 5.5-compatible images, validated, and then migrated into the ESXi 6.5 Production cluster.

02 / Project Drivers & Objectives

Why the modernization was required.

Project Drivers

  • Aging bare-metal server hardware and legacy operating systems were out of support or difficult to maintain.
  • The legacy environment did not provide clear separation between Production, STG, and QA workloads.
  • Backup protection had not been enabled on the existing systems, creating additional operational risk.
  • Infrastructure needed to be consolidated and standardized on a maintainable virtualization platform.
  • Legacy Linux servers needed to be preserved and migrated with minimal disruption.

Completed Objectives

  • Implemented a VMware-based Production platform with shared SAN storage and host clustering.
  • Established dedicated Production, STG, and QA environments.
  • Separated VMware management traffic from Production, STG, and QA workload traffic using VLAN segmentation and separate management switches.
  • Connected both virtual infrastructure areas to the existing firewall through their respective management switches.
  • Migrated legacy Linux workloads into VMware-compatible VM images and moved them to the target platform.

04 / Network and Access Structure

Compute, workload and storage traffic were deliberately separated.

  • The Production Management Switch provided Ethernet connectivity for the Production VMware Management VLAN, Production VLAN 1, and Production VLAN 2, and connected upstream to the firewall.
  • A separate STG/QA Management Switch provided Ethernet connectivity for the VMware Management VLAN, STG VLAN, and QA VLAN, and connected upstream to the firewall.
  • Production Ethernet/VLAN traffic remained separate from the Fibre Channel storage fabric.
  • The Fibre Channel switches connected only the Production ESXi hosts to the two HP P2000 SAN systems.
  • Workload VLAN separation reduced direct dependency between Production, STG, and QA traffic and provided a clearer operational boundary between environments.

07 / Legacy Server Migration

Controlled migration of older Linux systems.

The most technically challenging part of the project was converting older Linux systems into VMs that could run reliably on the new VMware platform. Some source systems were sufficiently old that direct conversion to ESXi 6.5 was not practical.

Migration PathLegacy Linux Server → VMware 5.5-compatible Image → VMware ESXi 6.5 Production Cluster

Migration Approach

  1. Existing legacy Linux systems were assessed for virtualization compatibility.
  2. Where direct conversion was not possible, the server was first converted into a VMware 5.5-compatible VM image.
  3. The intermediate VMware 5.5 image was validated before further migration.
  4. The validated VM was moved into the VMware ESXi 6.5 Production cluster.
  5. The migrated workload was checked in the target environment before being treated as the replacement for the legacy server.

Project Challenges

  • Legacy Linux operating systems and application dependencies created compatibility constraints.
  • Some workloads required a two-stage VMware migration path rather than direct migration to ESXi 6.5.
  • Older systems required additional validation to ensure converted VMs remained bootable and operational.
  • The project had to preserve Production services while introducing the new infrastructure and environment separation.

10 / Project Closure Summary

Modernization completed.

The VMware infrastructure modernization project was completed with a new virtualized Production platform and separate STG and QA environments. The implementation addressed major limitations associated with aging bare-metal systems and the lack of environment separation.

Legacy Linux workloads were migrated through a controlled conversion process, including an intermediate VMware 5.5 stage where required, before workloads were moved to the ESXi 6.5 Production cluster.

The completed architecture provided CBL with a more structured, supportable, and manageable server platform and established a clearer foundation for future infrastructure operations, maintenance, and workload lifecycle management.
