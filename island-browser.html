01 / Executive Summary

Secure internal application access without AVD as the front door.

Island Browser Integration was implemented to give employees and contractors secure direct access to internal Azure-hosted applications from their own computers. The completed design used Island Enterprise Browser and Island Private Access (IPA), with two separate IPA deployments in Azure—one for Employees and one for Contractors.

The solution provided browser-based access control, central administration, identity-aware application access, and device posture validation while reducing dependence on Azure Virtual Desktop for users who only needed secure browser-based access to internal applications.

02 / Project Background

Reducing access friction.

Previously, users were often required to connect to an Azure Virtual Desktop pool simply to reach internal web applications. This introduced additional steps, user friction, and management overhead. The project introduced a more direct and user-friendly access method using a centrally managed enterprise browser while preserving strong access controls.

03 / Project Requirements

Requirements delivered.

Access Requirements

  • Allow users to access internal Azure-hosted applications directly from their own computers.
  • Remove the need for users to sign in to an AVD pool just to reach internal web applications.
  • Provide separate secure access paths for Employees and Contractors.

Security & Administration

  • Enable centrally managed browser controls for users, devices, policies, and browser settings.
  • Validate device posture as part of the Zero Trust access decision.
  • Use browser-based sign-in and identity-aware access instead of legacy access methods.
04 / Implemented Solution

Island Enterprise Browser with two Azure IPA paths.

The completed solution used Island Enterprise Browser as the user access platform and Island Private Access to securely publish internal applications. Two separate IPA deployments were implemented in Azure: one for Employees and one for Contractors. Users signed in to the Island Browser and, once authenticated, were able to access authorized internal applications hosted in Azure without first accessing AVD.

Enterprise Browser

Island Enterprise Browser provided the secure browser-based workspace for end-user access.

Employee IPA

A dedicated Island Private Access deployment in Azure provided the private access path for employee traffic.

Contractor IPA

A separate IPA deployment provided an isolated private access path for contractor traffic.

05 / Platform Capabilities Applied

Browser-native control and private access.

  • Centralized browser management for users, devices, policies, and browser settings.
  • Secure access to private/internal applications using Island Private Access.
  • Browser-native Zero Trust access aligned to identity and device context.
  • Device posture evaluation to verify security conditions before granting access.
  • Managed access from user devices without relying on AVD as the access front door.

08 / Access and Security Flow

Identity-aware browser access with device posture.

1. User LaunchEmployee / Contractor Device → Island Browser

Employees and Contractors launched the Island Browser on their own computers.

2. Browser Sign-InUser → Organization Credentials → Island Browser

Users signed in to the browser with their organization credentials.

3. Central Policy EnforcementIsland Management Console → Browser Policies & Access Controls

The management console enforced centrally defined browser policies and access controls.

4. Device Posture EvaluationEncryption + Antivirus + OS Version + Managed State

Device posture was evaluated before allowing access.

5. Private Access RoutingAuthorized User → Employee IPA / Contractor IPA

Authorized users were routed through the appropriate Azure-based IPA deployment.

6. Application AccessIPA → Internal Azure Applications / Application Servers

The IPA connection provided secure access to the internal Azure-hosted applications and application servers.

09 / Administrative Model

Central browser governance.

Island Browser provided a centrally manageable browser platform. The administration team managed users, devices, policies, and browser settings from a single management console. This allowed security and IT teams to standardize access behavior, apply policy changes centrally, and govern browser-based access to internal resources without relying on users to manually manage separate secure-access clients.

10 / Zero Trust Alignment

Access based on identity and device context.

The implementation aligned with Zero Trust principles by evaluating both user identity and device context before allowing access to internal applications. Rather than granting broad network-level access, users authenticated in the browser and were allowed to reach only published internal applications through Island Private Access. Device posture validation strengthened the design by checking whether the endpoint met required security conditions.

11 / Technical Summary

Direct, secure application access for Employees and Contractors.

The Island Browser Integration project simplified secure access to internal Azure-hosted applications for employees and contractors. The previous approach required users to sign in to an AVD pool even when the only requirement was browser-based access to internal applications. The new design replaced that dependency with Island Enterprise Browser and Island Private Access.

Two IPA deployments in Azure separated Contractor and Employee access paths. Users signed in directly through the browser, after which access was governed by centrally managed policies and device posture checks. The Island Management Console provided administration of users, devices, policies, and browser settings. Device posture checks such as encryption status, antivirus status, operating-system version, and managed-device state were applied as part of the Zero Trust access decision.
