01 / Project Overview

Digitizing factory machinery operation data.

The Smart Factory Project was implemented to replace manual paper-based data collection with a digital system for capturing machinery operation data. The completed solution enabled users to enter production data through client tablets and store the information in a centralized system.

The captured operational data was then made available for reporting and analytics in Power BI, providing a structured digital path from factory data entry to centralized storage and business reporting.

02 / Business Need

Why the project was required.

Existing Process

  • Machinery operation data was written down on paper.
  • Manual recording made reporting slow, error-prone, and difficult to consolidate.

Business Requirement

  • A structured system was required to capture operational data electronically.
  • The captured data needed to be available for reporting and visualization in Power BI.
03 / Delivered Solution

A hybrid cloud and on-premises data-entry platform.

The IT team built and deployed a data-entry solution that allowed users to enter production data through client tablets. The Production application and database platform were hosted in Oracle Cloud, while Stage (STG) and Quality Assurance (QA) environments were maintained on-premises.

Factory Tablets→Factory Network→Site-to-Site VPN→Oracle Cloud Application→Production Database→Power BI

05 / Technical Architecture Summary

Hybrid production and non-production design.

  • The Production Application Server was deployed in Oracle Cloud.
  • The Production Database Server was deployed in Oracle Cloud.
  • The Production environment was connected to the on-premises factory network through a Site-to-Site VPN.
  • STG and QA servers were deployed on on-premises infrastructure.
  • Client tablets were connected within the factory network for user data entry.
  • Local client PCs and workstations were connected on the on-premises network for operations and support activities.
  • Operational data collected through the application was stored in the system and made available to Power BI for dashboards and reporting.
06 / Functional Flow

From factory tablet to operational analytics.

1. Data EntryUser → Client Application on Tablet

Users entered machinery operation data through the client application installed on tablets.

2. Factory NetworkTablet → On-Premises Factory Network

The entered data was transmitted through the factory network.

3. Secure Cloud ConnectionFactory Network → Site-to-Site VPN → Oracle Cloud

The on-premises network connected securely to the Production environment in Oracle Cloud through a Site-to-Site VPN.

4. Application ProcessingProduction Application Server → Operational Processing

The Production Application Server processed the submitted operational data.

5. Central StorageApplication Server → Production Database Server

The Production Database Server stored the operational records.

6. Reporting & AnalysisStored Data → Power BI

Power BI consumed the stored data for dashboards, reporting, and analysis.

07 / Environment Design

Production separated from testing and validation.

Production — Oracle Cloud

The live Production environment was hosted in Oracle Cloud and supported the Production Application Server and Production Database Server.

STG / QA — On-Premises

STG and QA environments remained on-premises to support testing, validation, and quality assurance activities without affecting live Production operations.

08 / Technical Summary

A completed hybrid Smart Factory platform.

The Smart Factory Project was completed as a hybrid architecture combining Oracle Cloud and on-premises infrastructure. Production Application and Database Servers were deployed in Oracle Cloud, and secure connectivity to the factory network was established through a Site-to-Site VPN terminating at the CBL firewall.

Within the on-premises environment, client tablets were used to capture machinery operation data digitally, replacing the previous paper-based process. STG and QA servers were deployed on-premises to provide separate non-production environments for testing and validation.

The operational data captured through the system was stored centrally and made available to Power BI for reporting and analytics. The implementation improved data accuracy, reduced manual effort, and enabled timely visibility into factory operations.
