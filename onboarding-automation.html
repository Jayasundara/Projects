Completed Automation Project

Employee Onboarding Request Automation

Automated the employee onboarding request process using Microsoft Power Automate to collect complete employee, access, software, licensing and cost requirements; provide IT early visibility; enforce HOD approval; and automatically create the final Jira onboarding ticket.

01 / Project Background

Replacing manual onboarding coordination.

The existing onboarding process required multiple manual exchanges between P&C, the employee's manager, HOD approvers and IT. Important system-access requirements, software needs and cost details could be missing when the onboarding ticket reached IT, creating delays and additional clarification work.

The project introduced a structured workflow that collected the required information in sequence and created the IT onboarding ticket only after the required approval was completed.

02 / Project Requirements

What the automation needed to achieve.

Process & Data Collection

  • Fast-track onboarding ticket creation and reduce manual email follow-up.
  • Collect basic employee information from P&C first.
  • Collect system access, application, software/license and cost requirements from the hiring manager.
  • Provide IT with early visibility that a new onboarding request was in progress.

Approval & Ticket Automation

  • Route access requirements and associated costs to the appropriate HOD for approval.
  • Create a Jira onboarding ticket automatically after HOD approval.
  • Notify P&C / HR when the onboarding ticket had been created.
  • Support rejection handling so requests could be corrected or reviewed.
03 / Implemented Automation Platform

Power Automate as the orchestration layer.

Microsoft Power Automate connected form submissions, SharePoint tracking, email notifications, approvals, IT alerting and Jira ticket creation so the onboarding request could move through the process without manual hand-offs between systems.

Microsoft Forms

Form 1 captured P&C / HR employee details. Form 2 captured manager-provided system access, software, licensing and cost requirements.

SharePoint Tracking

A central SharePoint record was created at the start and updated throughout the process, giving the workflow one consistent tracking source.

Approvals & Jira

HOD approval was enforced before Power Automate automatically created the onboarding ticket on the Jira board.

07 / SharePoint Tracking Design

A single source of workflow status.

A SharePoint list was used as the central tracking record for the onboarding workflow. The first form submission created the record, and the manager submission updated the same record with system access and cost requirements.

This provided one source of status information while the request moved from P&C to the manager, IT, HOD approval and Jira.

08 / Approval and Ticket Creation

Provisioning only after approval.

The HOD approval stage ensured that requested access and associated costs were reviewed before IT received the final implementation ticket. Power Automate handled the approval outcome.

Approved

Approved requests were converted automatically into Jira onboarding tickets containing the collected onboarding, access, software and cost details.

Rejected

Rejected requests could be returned to the appropriate stakeholders for correction or review instead of creating an incomplete IT implementation ticket.

09 / Technical Summary

A structured, trackable onboarding workflow.

P&C initiated the process by submitting structured new-employee information. Power Automate created a SharePoint tracking record and automatically emailed the hiring manager with the employee details and Form 2. The manager supplied system access, software, license, application and cost information, after which Power Automate updated the same SharePoint record and gave IT early notification that onboarding was in progress.

The completed requirements were then routed to the HOD for approval. Once approved, Power Automate automatically created the onboarding ticket on the Jira board and notified P&C / HR. The completed design improved data completeness, provided earlier IT visibility, reduced manual follow-up and enforced approval before provisioning.
