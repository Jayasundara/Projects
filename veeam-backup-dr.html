Veeam Backup & Disaster Recovery

Implemented a centralized Veeam Backup & Replication platform for VMware and additional servers, introduced dedicated NAS backup storage, and established an off-site VMware disaster recovery environment connected through a secure Site-to-Site VPN.

01 / Executive Summary

From no standardized backup platform to centralized protection and off-site recovery.

CBL did not have a standardized server backup and disaster recovery solution. The project implemented Veeam Backup & Replication to protect the production VMware environment and additional servers, with a NAS device connected as the primary backup repository. A separate VMware recovery environment was deployed at a subsidiary location to provide an off-site disaster recovery capability.

The primary and DR locations were connected through a Site-to-Site VPN. Veeam replication capabilities were used to maintain recoverable copies of selected VMware workloads at the DR site. This provided centralized backup management, local backup storage, and an independent recovery location in the event of a major production-site outage.

02 / Business Requirements

What the project needed to deliver.

Backup Requirements

  • Establish a centralized and manageable server backup platform.
  • Protect production VMware virtual machines and other business servers.
  • Store server backups on dedicated backup storage instead of relying on the production infrastructure.

Disaster Recovery Requirements

  • Provide an off-site disaster recovery environment at a subsidiary location.
  • Replicate critical VMware workloads to the DR site over secure Site-to-Site VPN connectivity.
  • Improve recovery capability following server failure, storage failure, site outage, or other disruptive events.
03 / Implemented Solution

Completed backup and recovery platform.

  • A Veeam Backup & Replication Server was deployed at the CBL primary site.
  • The production VMware environment was added to Veeam and protected through image-level VM backup jobs.
  • Additional physical / non-VMware servers were brought under backup protection, using Veeam Agent-based protection where applicable.
  • A NAS device was connected to the Veeam environment and configured as the primary backup repository.
  • A separate VMware server was deployed at a subsidiary location to provide disaster recovery capacity.
  • A Veeam DR replication server / VM was deployed in the subsidiary VMware environment as part of the DR implementation.
  • The primary and DR sites were connected through a Site-to-Site VPN terminating on the site firewalls.
  • Veeam replication was configured to create recoverable VMware replicas at the DR site.
04 / Technical Architecture

Implemented Veeam Backup and Disaster Recovery architecture.

The completed design separated local backup storage from production compute and added a second VMware environment at a subsidiary site for recovery. Backup and replication traffic followed controlled network paths between the primary Veeam server, NAS repository, protected workloads, and the DR site.

05 / Backup Design

Centralized management with dedicated backup storage.

The Veeam Backup & Replication Server was used as the central control point for the backup environment. Production VMware virtual machines were protected using Veeam image-level backups. Additional servers were included in the backup scope using the appropriate Veeam protection method for the workload.

The NAS was configured as the primary backup repository. This separated backup data from production compute and provided a dedicated storage target for restore points. Backup jobs could therefore be managed centrally while the backup files were stored on dedicated network-attached storage.

06 / Disaster Recovery Design

Independent recovery capacity at a subsidiary site.

A second VMware environment was installed at a subsidiary location to provide recovery capacity outside the primary site. The two sites communicated through a Site-to-Site VPN. Veeam replication jobs were used to maintain VMware replicas on the target DR host so that selected workloads could be brought online at the subsidiary site if the primary production environment became unavailable.

For VMware workloads, the design was also relevant to Veeam's Replica from Backup capability, which can use an existing Veeam backup chain as the data source rather than reading the VM again from production. This is particularly relevant where a local NAS repository already contains the backup restore points used for DR replication.

08 / Backup and Replication Flow

Backup, replication, recovery and failback workflow.

1. Protect WorkloadsVMware VMs + Other Servers → Veeam Backup & Replication

Veeam processed the protected VMware VMs and other servers at the primary site.

2. Store Restore PointsVeeam → NAS Backup Repository

Backup restore points were written to the NAS backup repository.

3. Replicate DR WorkloadsPrimary Site → Site-to-Site VPN → DR Site

For DR-protected VMware workloads, Veeam replication transferred the required VM data across the secure VPN.

4. Maintain Recovery CopiesDR VMware Host → Replicated VMs

Replicated VMs were created and maintained on the VMware host at the subsidiary DR site.

5. Recover During OutagePrimary Site Unavailable → DR Replica Used as Recovery Copy

If the primary site became unavailable, the replicated VM could be used as the recovery copy at the DR site.

6. Return to ProductionDR Replica → Veeam Failback → Production

After primary-site recovery, Veeam failback capability could be used to return service to the production environment as part of the DR procedure.

10 / Technical Summary

Combined local backup and off-site recovery.

The project replaced the previous lack of a formal server backup solution with a centralized Veeam Backup & Replication platform. The primary Veeam server protected VMware virtual machines and additional servers, while a dedicated NAS provided local backup repository capacity. This gave the IT team a central location from which backup jobs and restore points could be managed.

The solution was extended into a disaster recovery architecture by deploying a separate VMware server at a subsidiary site. The DR site was connected to the primary site through a Site-to-Site VPN, and Veeam replication was used to maintain recovery copies of selected VMware workloads on the remote VMware host. This created a recovery location independent of the production site and reduced exposure to a single-site infrastructure failure.

11 / Project Closure

Implementation completed.

The Veeam Backup and Disaster Recovery implementation was completed as a combined local-backup and off-site recovery solution. CBL gained centralized server protection, dedicated backup storage, secure replication to a subsidiary site, and a defined technical platform for restoring critical VMware workloads during a major production outage.
