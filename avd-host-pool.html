Completed Azure Infrastructure Project

Azure Virtual Desktop Host Pool Setup

Implemented a centralized and secure Azure Virtual Desktop environment using multiple Windows session hosts, Microsoft 365 identity-based access, FSLogix profile containers stored in Azure Storage, and hybrid identity integration through on-premises Active Directory and Microsoft Entra Connect.

01 / Project Overview

Centralized Azure-hosted Windows desktops.

The Azure Virtual Desktop host pool project delivered a centrally managed Windows desktop environment in Microsoft Azure. Users connected through the Azure Virtual Desktop client and authenticated using their existing Microsoft 365 / Office 365 identities.

Multiple session hosts were deployed within the host pool to provide user sessions and scalable capacity. The environment was integrated with the organization’s existing hybrid identity architecture so existing users and groups could be used for access and authorization.

02 / Project Requirements

Requirements delivered.

Secure User Access

  • Provide secure remote access to an Azure-hosted Windows desktop environment.
  • Allow users to authenticate using their existing Microsoft 365 / Office 365 accounts.
  • Publish assigned desktop resources through the AVD workspace and application group.

Scalability, Profiles & Identity

  • Deploy multiple session hosts within a single Azure Virtual Desktop host pool.
  • Store user profiles centrally so the same profile follows the user across hosts.
  • Integrate AVD with the existing hybrid Active Directory identity environment.
  • Provide a design that could expand with additional session hosts as required.
03 / Implemented Solution

Host pool, workspace, identity and profile services.

An Azure Virtual Desktop host pool was created with multiple Windows session hosts. Users accessed assigned desktop resources through the AVD workspace and application group. The session hosts were integrated with the organization’s hybrid identity environment, allowing existing users and groups to be used for access and authorization.

04 / Completed Architecture

Implemented AVD host pool architecture.

The original completed architecture diagram is shown below. It documents client PCs, the AVD workspace and application group, multiple session hosts, Microsoft Entra ID authentication, Microsoft Entra Connect synchronization, on-premises Active Directory, and FSLogix profile containers hosted in Azure Storage.

Figure 1. Azure Virtual Desktop Host Pool - Completed Architecture

AVD Session Delivery

Multiple Windows multi-session hosts within a single host pool accepted user connections and delivered centralized desktop sessions.

Centralized Profiles

FSLogix profile containers stored in an Azure Storage Account allowed user settings and application profile data to roam between session hosts.

Hybrid Identity

Microsoft Entra Connect synchronized users and groups from on-premises Active Directory to Microsoft Entra ID for consistent organizational identity across Microsoft 365 and AVD.

06 / User Profile Management

Consistent user experience across hosts.

FSLogix profile containers were used to provide persistent user profiles across the AVD session hosts. The user profile was stored centrally in the Azure Storage Account and attached when the user signed in. This allowed user settings and application profile data to follow the user between hosts in the pool.

07 / Hybrid Identity Integration

Microsoft 365 and on-premises identity working together.

The AVD environment was integrated with the existing on-premises Active Directory environment using Microsoft Entra Connect, formerly Azure AD Connect. Users and groups were synchronized to Microsoft Entra ID so the same organizational identity could be used for Microsoft 365 and Azure Virtual Desktop access, while the session-host environment remained part of the organization’s hybrid identity model.

08 / User Connection Flow

From client PC to persistent AVD session.

1. Launch AVD ClientClient PC → Azure Virtual Desktop Client

The user launched the Azure Virtual Desktop client from a client PC.

2. AuthenticateUser → Microsoft 365 / Office 365 Identity

The user authenticated using their Microsoft 365 / Office 365 account.

3. Resource AssignmentAVD Service → Workspace / Application Group

Azure Virtual Desktop presented the resources assigned through the workspace and application group.

4. Session PlacementHost Pool → Available Session Host

The user session was established on an available session host in the host pool.

5. Profile AttachmentAzure Storage → FSLogix Profile Container → Session Host

FSLogix attached the user’s profile container from the Azure Storage Account.

6. Consistent ExperienceAny Session Host → Same User Profile & Settings

The user received the same profile and settings regardless of which session host accepted the session.

09 / Technical Summary

A scalable hybrid-identity desktop platform.

The Azure Virtual Desktop Host Pool project was completed as a centralized remote desktop solution hosted in Microsoft Azure. Users connected through the Azure Virtual Desktop client and authenticated using their Microsoft 365 identities. Multiple session hosts within the same host pool provided scalable session capacity.

FSLogix profile containers stored in an Azure Storage Account centralized user profiles and allowed them to roam between session hosts. Microsoft Entra Connect integrated the AVD environment with the organization’s existing on-premises Active Directory, providing a hybrid identity model. The final design simplified user access, centralized profile management, and established a scalable AVD platform.
